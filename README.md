# ProFluency autopost

Posts the "Pull up a chair" month (Mon 19 Oct – Sun 15 Nov 2026) to @profluencyuk by itself: 74 items (58 stories, 8 feed posts, 8 Reels), each at its planned UK time. From 29 Oct 2026 the hashtags go at the end of the caption, and no first comment is posted. Your computer can be off. It runs free on GitHub: every 15 minutes a small script (`publish.py`) checks the schedule and posts whatever is due through Instagram's official API.

Everything posts automatically, including the stories that were made for stickers (question, poll, countdown, link) and the Sunday "Your answers" stories. The API can't add stickers or other people's replies, so those items carry a `follow_up` note: once one has posted, GitHub opens an issue, which emails you what it was made for. If you want the sticker, save the story from Instagram and post it again with the sticker. An item with `"manual"` instead of `"follow_up"` is never posted: you're emailed at its time to post it yourself.

## What's here

- `schedule.json`: the items, with time (Europe/London, clocks-change aware), type, file and caption, all copied from the month pack. `first_comment` is kept empty: it isn't posted any more.
- `docs/media/`: the files, renamed for the web (e.g. `2026-10-19-1930-reel.mp4`). Stories use the animated MP4 wherever one exists. Story videos have a silent audio track added, which Instagram's API expects. Reels need real sound (see "Posting rhythm").
- `publish.py`: the poster. It uses Python's standard library only.
- `.github/workflows/autopost.yml`: the 15-minute timer, a record of what's been posted (`posted.json`), and the email reminders.
- `SETUP_PROMPT.md`: paste this into Claude Code or Cursor in your terminal and it walks you through setup.

## One-off setup (about 30 minutes)

1. **Instagram:** make @profluencyuk a **Business** account (Settings › Account type and tools). A Creator account can't publish Stories through the API.
2. **Meta developer app:** at developers.facebook.com, create an app with the Instagram API ("API setup with Instagram login"), add @profluencyuk and generate a token. Grant `instagram_business_basic`, `instagram_business_content_publish` and `instagram_business_manage_comments`. Copy the **access token** (it lasts 60 days, which covers the month) and the **Instagram user ID**.
3. **GitHub:** push this folder to a **public** repository (free timer minutes and free hosting for the media). Turn on GitHub Pages from `main` › `/docs`. Add the secrets `IG_ACCESS_TOKEN` and `IG_USER_ID`, and the variable `MEDIA_BASE_URL` = `https://<your-github-name>.github.io/<repo>/media`.
4. **Test:** Actions › Instagram autopost › Run workflow. Run it with `check`, which tests the token, account type and every media link, then with `dry-run`. Nothing is posted in either mode.

Once that's done, it starts by itself. The first automatic post is **Mon 19 Oct 12:30**; the 08:30 story that day is one of the by-hand ones.

## Posting rhythm (from 29 Oct 2026)

- **Stories:** at most 2 a day, at 11:00 and 18:00 UK time.
- **Carousels:** 1 or 2 a week, on Tuesday and Saturday. No more single-image feed posts.
- **Reels:** 2 or 3 a week, on Monday, Wednesday and Friday at 19:30, shared to the feed. Each Reel should be 15 to 30 seconds long with real sound (music you have the rights to, or a voiceover) in the MP4 itself. The API can't add music from Instagram's library, and `publish.py` doesn't check a Reel's length or sound, so check them before they're scheduled.
- **Carousels in `schedule.json`:** `"type": "carousel"`, with `"slides"` listing 2 to 10 files in order (all 4:5, 1080 × 1350) and `"media"` set to the first slide. The caption ends with 3 to 5 hashtags.
- **On hold:** an item with `"hold": "<why>"` is never posted or emailed. It stays in `schedule.json` so nothing is lost; `python3 publish.py --list` shows it as "on hold". Delete the `hold` line (and set a new `post_at`) to post it, or use `--only <id>`.
- **Facebook:** this repo only posts to Instagram. It never posts to the Facebook Page; anything that appears there comes from the sharing settings in the Instagram app, not from here.

## Good to know

- **Timing:** posts go out within about 15 minutes of the planned time. GitHub's timer can occasionally run late. If a post is more than 3 hours late it's skipped, and you get an email instead, so nothing lands at a strange hour.
- **Reel sound:** the API can't add music from Instagram's library, so a Reel's sound has to be in its MP4. If you want a trending sound instead, set that Reel to by hand (add `"manual": "Add a sound"` to it in `schedule.json`).
- **Public repo:** the files and captions can be seen by anyone who finds the repository before they're posted. If that matters, keep the repo private and host `docs/media` on profluency.co.uk instead (then set `MEDIA_BASE_URL` to that folder). The 15-minute timer stays inside GitHub's free private allowance.
- **Changing a post:** edit `schedule.json` (text, time) or replace a file in `docs/media`, then commit. To stop everything, disable the workflow in Actions.
- **Commands** (run with the three settings in your environment): `python3 publish.py --check`, `--dry-run`, `--list`, or `--only <id>` to post one item now.
- **Limits:** Instagram allows 50 API posts per 24 hours. With the rhythm above, the busiest day has 3.
- **Token renewal:** `.github/workflows/refresh-token.yml` renews the Instagram token on the 1st and 15th of each month and writes the new expiry date to `token-status.json`. It needs one secret, `SECRETS_WRITER_TOKEN`: a fine-grained GitHub token for this repo only, with "Secrets: Read and write". If a renewal fails, you get an issue email.
- **Where it runs (from 22 Oct 2026):** the posting runs on your own machine, not GitHub's servers, after Meta blocked access twice while posts came from GitHub's shared addresses. The workflow only runs on a self-hosted runner with the label `autopost`; GitHub still keeps the timer, the secrets and `posted.json`. To set up the Mac, run this in Terminal and follow what it says: `bash <(curl -fsSL https://raw.githubusercontent.com/cjgraham-hue/profluency-autopost/main/tools/setup-mac-runner.sh)`. Keep the Mac on, plugged in and awake from 7am to 10pm; if it's asleep at a post's time, the post goes out when it wakes, up to 3 hours late, otherwise you get the usual missed-post email. The token renewal and the weekly media cleanup still run on GitHub's servers. Because this repository is public, set Settings › Actions › General › "Fork pull request workflows from outside collaborators" to **Require approval for all outside collaborators**, so nobody else's code can ever run on your machine.
- **Moving to the Raspberry Pi later:** on the Pi, open the repository's Settings › Actions › Runners › New self-hosted runner, choose Linux and ARM64, and run the commands it shows; when it asks for labels, type `autopost`. Then run `./svc.sh install` and `./svc.sh start` (both with `sudo` on Linux). Once the Pi shows as Idle, stop the Mac one: in `~/profluency-runner` on the Mac run `./svc.sh stop`, `./svc.sh uninstall`, then remove it from the same Runners page. Nothing in the workflow changes.
- **Staying clear of Instagram's automation checks:** each post goes out up to 12 minutes after its planned time (a different amount for each). If Meta blocks access ("API access blocked", a restricted account, suspected spam or a dead token), posting pauses straight away: `pause.json` is written, you get one email, and nothing is tried again. Clear the notice in the Instagram app, then run Actions › Instagram autopost › Run workflow with `check`. If the account answers, `pause.json` is removed and posting carries on at the next run; anything more than 3 hours late by then is reported as missed.
- **Weekly media cleanup:** `.github/workflows/cleanup-media.yml` runs every Monday before the first post and removes the earlier weeks' files from `docs/media` once they've posted (or been posted by hand), plus any file a restyle replaced. Anything not yet posted stays, and a missed item's file stays for four weeks in case you want to post it with `--only`. The originals are in Drive's "Social media backup", and git history keeps every removed file. To preview it, run it from Actions with `dry-run`; `python3 tools/cleanup_media.py --dry-run` does the same locally.
- **New months:** Claude makes each month (plan, artwork, animations, InDesign backup in Drive) and, once you say "schedule it", adds the media to `docs/media` and the posts to `schedule.json` here.
- **Hub feed (from 30 Oct 2026):** `.github/workflows/hub-feed.yml` runs `tools/hub_feed.py` on the same Mac runner every two hours from 06:41 to 20:41 UTC, and straight after a click in Cameron's private hub. It posts the comment replies he pressed Send on (never anything else), merges or closes this repo's pull requests he approved or declined there, and sends the hub the account's numbers, recent posts and the comments still waiting for a reply. It needs two repository secrets, `HUB_SYNC_TOKEN` and `HUB_URL` (both secrets, so the hub's address never appears in this public repo's logs), and optionally `FB_PAGE_ID` and `FB_PAGE_TOKEN` for the Facebook Page. Reach, saves and shares need `instagram_business_manage_insights` on the token; without it the hub shows likes and comments. If `pause.json` is present it leaves Instagram alone. Its logs show counts only.
- **Pinterest and YouTube:** from December 2026 each month also has a pin for every feed post or Reel and a YouTube Short for every Reel. This repo doesn't post them. Claude schedules them in Pinterest and YouTube Studio through Chrome. The pin images go in `docs/pins/<YYYY-MM>/`, which the weekly cleanup never touches. The list of pins and Shorts, with what's been scheduled, is in `platforms/platforms-<YYYY-MM>.json`, so a follow-up chat can finish anything Pinterest's 30-day limit held back.
